## Exact deterministic result

Extract `qcom,fg-profile-data = [ ... ];`, decode exactly 416 hexadecimal bytes from each input, then compare all byte indices **0–415**. Both arrays are length **416**, mismatch indices are **empty**. Therefore source bytes are **identical**, not merely similar, and the 24-byte load-comparator prefix is naturally identical. Last nonpadding word `0x0E04` = **3588mAh** for *both*. Thus the OP4300 label exceeds the internal capacity by **712mAh**; the label cannot be interpreted as a measurement made by the Gen4 profile. This result is independent of the entire source files having distinct Git SHA-1, because their metadata differ.

A structured comparison of `qcom,... = ...;` properties in these two DTSI nodes found **12 fields whose literal text differs/is omitted** and **10 common property fields whose values match**; the 416-byte property itself is one of the matching ones and is separately verified at the byte level. Differing/omitted source properties:

1. `max-voltage-uv`: 4350000 → 4420000.
2. `fastchg-current-ma`: 5400 → 3000.
3. `jeita-fcc-ranges`: intermediate band 3600000 → 5400000; this differs from the nominal max charging current and is not necessarily the applied value.
4. `jeita-fv-ranges`: intermediate band 4350000 → 4420000.
5. `jeita-hard-thresholds`: present only Alium.
6. `jeita-soft-thresholds`: present only Alium.
7. `jeita-soft-hys-thresholds`: present only Alium.
8. `jeita-soft-fcc-ua`: present only Alium.
9. `jeita-soft-fv-uv`: present only Alium.
10. `batt-id-kohm`: 107 → 200.
11. `fg-cc-cv-threshold-mv`: 4340 → 4380.
12. `battery-type`: Alium 3600 → OP 4300.

The precise intended reason for reuse is unknown. Possible explanations include a provisioning placeholder, a ported reference or a vendor policy reuse. **Do not assert which explanation is true.** No evidence from these two files establishes that the two *physical* battery cells have equivalent electrical characteristics.

## Critical correction to future Gen4 validation

- PM855GUI checksum and correct 416B length **do not authenticate cell identity**. Multiple *nominally different* real source definitions can carry byte-identical Gen4 profiles.
- A matched QG/Gen4 named-family cross-format pair cannot be multiplied into independent training samples by counting files where the same Gen4 416-byte array was copied under a different commercial label. **Deduplicate on entire payload identity**, ideally plus genuinely independent cell characterization provenance.
- Gen4 block data and external metadata are physically separate in Device Tree. Distinct battery-type, charge-voltage, JEITA and ID properties can be attached to the **same** payload, so the 24-byte comparator does not discriminate those metadata changes. Conversely, changing only the metadata does not magically create a 4300/5850/6000mAh-specific calibrated Gen4 model.
- This reinforces the previous observation that Android 17 Butterflies `5k` simply selects an existing J3S profile in the actual alioth DTBO; relabeling to `Nohon_BN61_6000mAh` cannot validate it.
- In this user's hardware, the declared NOHON BN61 max charge voltage **4.45V** remains a hard safety input. Do not copy any other device's voltage policies or produce a flashable BN61 profile until independent pack-specific electrical data exist.

## Data status

**CONFIRMED by source byte comparison:** all 416 bytes identical, both 0x1538 checksum labels, normal/cold Rslow arrays identical, 12 external property differences; distinct named capacities, battery IDs, charger thresholds.

**NOT proven:** actual OnePlus OP4300 cells are electrically equivalent to Alium 3600; manufacturer's reason for reusing the file; exact currently installed user's FG SRAM; a QG→Gen4 transfer; the NOHON electrical profile.

No `-6K` ZIP/DTBO/boot image created. This report is a **negative control that prevents false positives**, not a reconstruction of missing NOHON battery calibration.
